# Финансы и цели — спецификация

> Брейнсторм 14.10.2026. Дополняет спецификацию MVP (`2026-10-06-diary-mvp-design.md`), не заменяет её.
> Внешний вид вкладок «Финансы» и «Цели» решается отдельно в Claude Design — здесь только данные, правила и функции.

## 1. Цель и критерий успеха
Приложение — посредник между жизнью пользователя и ежемесячным разбором в Claude Code на ПК. К дневнику добавляются:
- **финансы** — доходы и траты по своим категориям, у категорий трат — степень важности;
- **цели на месяц** — пишутся текстом в начале месяца, по желанию измеряются тратами, доходами или метриками;
- **привычки** — уже есть: это метрики «да/нет» и «число» из «Настроек → Метрики»; отдельной сущности не нужно.

Раз в месяц пользователь экспортирует дневник, Claude в сессии `LIFE/` читает каждый день, разносит события по ЛИЧНОЕ
и сверяет цели (процедура разбора — вне этого репозитория).

**Успех:** ноябрь 2026 прожит с целями и полным учётом денег; в конце месяца приложение показывает доход, траты,
«отложено», траты по важности и категориям, прогресс измеримых целей, а экспорт содержит всё это для Claude.

## 2. Объём и порядок
**Часть 1 (эта спецификация, сейчас):** схема v2, категории, операции, цели, итоги месяца, прогресс целей,
экспорт и импорт `formatVersion: 2`. Чистые функции в `domain/` + функции доступа в `db/`, всё с тестами.
**Часть 2 (после макетов Claude Design):** вкладки «Финансы» и «Цели», блок «Категории» в «Настройках»,
строка операций за день в «Итоге». Функции экранов — §6; вид — по макетам.

Публикация (push в `main`) — один раз, после части 2, версией 1.2.0. Часть 1 без экранов на телефон не уходит.

**Не входит:** напоминания о тратах, лимиты в категориях (лимит — это цель), несколько валют, счета и переводы между
ними, сверка с банковской выпиской (её делает Claude на ПК), цели по метрикам типа «время».

## 3. Данные — схема `diary` v2
`db.version(2).stores(...)` добавляет три таблицы; v1 не меняется. `meta.schemaVersion` = 2.
Все суммы — **целые копейки**, валюта одна (₽).

| Таблица | Ключ / индексы | Поля |
|---|---|---|
| `financeCategories` | `key` | `key`, `kind` (`expense` / `income`), `name`, `importance` (только у `expense`: `need` / `useful` / `optional`), `order`, `archived`, `createdAt`, `updatedAt` |
| `transactions` | `id`; `day`, `updatedAt` | `id` (UUID), `day` (ГГГГ-ММ-ДД), `kind` (`expense` / `income`), `amount` (копейки, > 0), `categoryKey`, `note?`, `createdAt`, `updatedAt`, `deletedAt` |
| `goals` | `id`; `month`, `updatedAt` | `id` (UUID), `month` (ГГГГ-ММ), `text`, `area`, `target?`, `order`, `createdAt`, `updatedAt`, `deletedAt` |

**Важность** (подписи в интерфейсе и экспорте): `need` «Необходимо», `useful` «Полезно», `optional` «Можно без этого».
Задаётся только у категории; у операции её нет. Смена важности категории меняет и итоги прошлых месяцев — это ожидаемо.

**Стартовые категории** засеваются в `initDb`, если таблица пуста, с меткой `SEED_TIME` (как метрики):
- траты: Продукты, Жильё и связь, Транспорт, Здоровье — `need`; Учёба, Спорт, Одежда, Подарки, Другое — `useful`;
  Кафе и доставка, Развлечения — `optional`;
- доходы: Зарплата, Подработка, Подарки и переводы, Другое.

Ключи категорий — латиница (`groceries`, `salary`, …); у новых, созданных пользователем, — `c_` + короткий UUID.
Категорию нельзя удалить — только архивировать: её операции остаются и считаются в итогах.

**Операция.** `day` по умолчанию — текущий логический день (граница из `meta.boundaryHour`), пользователь может
выбрать любой. `kind` операции совпадает с `kind` её категории. Удаление — мягкое (`deletedAt`).

**Сфера цели** (`area`): `finance` Финансы, `work` Работа, `study` Учёба, `health` Здоровье, `relations` Отношения,
`other` Другое. Нужна Claude, чтобы разносить итоги по разделам ЛИЧНОЕ.

**Измерение цели** (`target`, необязательно):
```ts
type Target =
  | { kind: 'finance'; measure: 'expense' | 'income' | 'saved';
      filter?: { categoryKey: string } | { importance: Importance };   // только для expense / income
      op: 'le' | 'ge'; value: number }                                 // копейки
  | { kind: 'metric'; metricKey: string; aggregate: 'count' | 'sum' | 'avg';
      op: 'le' | 'ge'; value: number }
```
Допустимые агрегаты метрик: `bool` — `count` (дни с «да»); `number` — `sum`, `avg`; `scale` — `avg`.
Метрики типа `time` не измеряются.

## 4. Логика (`src/domain/`, чистые функции с тестами)
- **`money.ts`** — `parseAmount("1 250,50") → 125050`: пробелы и неразрывные пробелы игнорируются, запятая и точка —
  десятичный разделитель, не больше 2 знаков после него; ошибка, если ≤ 0, не число или > 100 000 000 ₽.
  `formatMoney(125050) → "1 250,50 ₽"`, целые рубли без копеек: `"1 250 ₽"`.
- **`finance.ts`** — `monthSummary(transactions, categories, month)`: доход, траты, `saved` = доход − траты
  (может быть < 0), траты по важности, траты и доходы по категориям (по убыванию суммы); удалённые операции не
  считаются. `dayTotals(transactions, day)` — доход и траты за день и число операций (строка в «Итоге»).
  `categoriesByUse(transactions, categories, kind)` — активные категории по частоте использования за последние
  90 дней, при равенстве — по `order` (порядок кнопок при быстром вводе). Создание и правка категорий и операций —
  функции в стиле `createMetric` (новая запись с метками времени).
- **`goals.ts`** — `goalProgress(goal, data)` для цели с `target`: текущее значение, цель, `remaining`
  (сколько осталось набрать или сколько ещё можно потратить), `state`:
  - `ge` — `done`, когда значение ≥ цели; иначе `progress`;
  - `le` — `over`, когда значение > цели; иначе `within` до конца месяца и `done` после;
  - месяц закончился, а `ge` не набрано — `missed`.
  Для метрик учитываются заполненные неудалённые дни месяца; `avg` по дням, где значение есть; нет дней — значения нет.
  Цель без `target` прогресса не имеет — её сверяет Claude по записям дней.

## 5. Экспорт и импорт — `formatVersion: 2`
**`backup.json`** добавляет `financeCategories`, `transactions`, `goals` (все, включая удалённые и архивные).

**Markdown** (`entries_…md`):
- в выборку попадает день, если после `lastExportAt` изменилась его запись **или** любая его операция; день только с
  операциями (без текста и метрик) тоже выводится;
- после строки метрик — строки операций, пустые пропускаются:
  ```
  Доходы: 50 000 ₽ — Зарплата 50 000
  Траты: 1 250 ₽ — Продукты 800 · Кафе и доставка 450 (кофе с Машей)
  ```
  внутри строки — по категориям по убыванию суммы, комментарии в скобках после категории;
- в начале файла — раздел целей каждого месяца, к которому относятся дни файла:
  ```
  # Цели — ноябрь 2026
  - [Финансы] Тратить на кафе не больше 5 000 ₽ — сейчас 3 200 ₽, в рамках
  - [Учёба] Закончить курс по SQL
  ```

**Ежемесячный разбор опирается на `backup.json`**, а не на Markdown: Markdown содержит только изменённое с прошлого
экспорта, а еженедельный экспорт-бэкап делает его неполным для месяца. Это правило передаётся в процедуру разбора LIFE.

**Импорт:** файлы `formatVersion` 1 и 2 принимаются; > 2 — отклоняются с просьбой обновиться. Новые массивы
проверяются как остальные (типы полей, `amount` — целое > 0, `kind`/`importance`/`area`/`target` из допустимых
значений) и сливаются так же: категории по `key`, операции и цели по `id`, побеждает более свежий `updatedAt`.
Сводка перед импортом добавляет «Операций: будет добавлено N, обновлено M. Целей: …».

## 6. Функции экранов (часть 2, вид — Claude Design)
Нижняя панель: **Итог · Финансы · Цели · Календарь · Настройки**.
- **Финансы:** месяц с переключателем; доход, траты, «отложено»; траты по важности (три уровня) и по категориям;
  доходы по категориям; список операций по дням, тап — правка или удаление. Быстрый ввод: «+» → сразу цифровая
  клавиатура → сумма → тап по категории сохраняет. Переключатель «Трата / Доход» (по умолчанию «Трата»),
  день (по умолчанию сегодня), комментарий — свёрнут. Цель — 5 секунд на трату.
- **Цели:** цели месяца с переключателем (можно заранее заполнить следующий и смотреть прошлые); у измеримых —
  прогресс и `remaining`; добавить и править: текст, сфера, «Измерять» → вид и условие; удалить; порядок.
- **Итог:** строка «Сегодня: траты 1 250 ₽ (3) · доход 0 ₽» с переходом к операциям дня — для вечерней сверки с банком.
- **Настройки → Категории:** траты и доходы отдельно; название, важность (у трат), порядок, архив, добавить.
