# Diary MVP — спецификация

> Утверждено в брейнсторме 06.10.2026. Обоснования и варианты установки — в `ОПИСАНИЕ.md`.
> Макеты: Claude Design «Дневник — палитры» (https://claude.ai/artifact/4qTAKHzpewv4E3fPZtASiq),
> доски «Мордочки „от руки“» и «Итог дня · олива + мордочки».

## 1. Цель и критерий успеха
Вечерний дневник на iPhone: перед сном за 1–3 минуты отметить настроение, скуку, сон и надиктовать, как прошёл день.
Записи в течение дня в приложении не ведутся (днём — заметки или Telegram, вечером перенос).
Прошлый опыт: Dailybean брошен из-за неудобной дневной записи и забывчивости → ставка на вечерний ритуал,
серию дней и напоминание в фиксированное время.

**Успех MVP:** месяц ежедневных записей без потери данных и хотя бы один экспорт, разобранный Claude на ПК.

## 2. Объём MVP
**Входит:** экраны Итог / Календарь / Настройки; настраиваемые метрики; серия дней; экспорт zip и импорт JSON;
баннер-напоминание о бэкапе; офлайн-работа; светлая и тёмная тема.

**Не входит:** дневная лента мыслей, защита (PIN, Face ID, шифрование), импорт из Dailybean, графики и дашборды,
цифра на иконке, виджет iOS, синхронизация.

## 3. Экраны
Нижняя панель: **Итог · Календарь · Настройки**.

### Итог
- Всегда открывает текущий **логический день** (граница 06:00). Переключателей дат нет.
- Шапка: надпись «Итог дня», дата шрифтом с засечками («Вторник, 6 октября»), справа чип серии с огоньком «12 дней».
- Карточки сверху вниз в порядке `order` активных метрик: Настроение (5 мордочек), Скука (5 мордочек), Сон (Лёг / Встал
  через системный выбор времени, справа длительность «7 ч 30 мин»). Новые метрики — тоже карточками.
- Карточка «Как прошёл день» — большое поле на всю оставшуюся высоту, без ограничения длины, диктовка клавиатурой iOS.
- **Автосохранение** каждого изменения (текст — с задержкой ~500 мс). Кнопки «Сохранить» нет.
- Повторный тап по выбранной мордочке снимает выбор.
- Баннер «Сделай бэкап» сверху, если с последнего экспорта прошло > 7 дней или экспорта не было, а записей ≥ 3.

### Календарь
- Сетка месяца, начало недели — понедельник; свайп или стрелки — соседние месяцы.
- День окрашен цветом настроения; заполненный без настроения — точка; пустой — серый; будущие неактивны.
- Тап по сегодняшнему или прошедшему дню → форма итога этого дня поверх календаря (та же, что на «Итоге»),
  закрытие возвращает в календарь.

### Настройки
- Метрики: добавить (название + тип), переименовать, изменить порядок, архивировать / вернуть из архива.
- Граница дня (по умолчанию 06:00, шаг 1 час, 00:00–08:00).
- Экспорт, импорт, дата последнего экспорта.
- Версия приложения.

## 4. Правила
- **Логический день:** время до границы относится к предыдущей дате. Запись 6 октября в 02:30 → день `2026-10-05`.
  Дата считается по местному времени устройства.
- **Заполненный день:** есть хотя бы одно значение метрики или непустой текст.
- **Серия:** число подряд идущих *засчитанных* дней, заканчивающихся сегодня. День засчитан, если в свой логический
  день (до границы следующего утра) заполнены все активные метрики и текст не короче 40 символов; момент хранится в
  `completedAt` дня и потом не снимается. Заполненный задним числом день в серию не идёт (уточнено пользователем
  06.10.2026 после проверки 1.0.0). Если сегодня ещё не засчитан — считаем от вчера; чип говорит «Заполни сегодня все
  метрики и 40+ символов текста, чтобы продлить». Серия обнуляется, только когда незасчитанный день закончился.
- **Длительность сна:** если «Встал» ≤ «Лёг», сон переходит через полночь (23:40 → 07:10 = 7 ч 30 мин).
  Показывается, только когда заполнены оба значения.

## 5. Архитектура
PWA: React + TypeScript + Vite, Dexie.js (IndexedDB), vite-plugin-pwa, Tailwind CSS, Vitest.
Адрес навсегда: **`https://sergeulub.github.io/diary-app/`**, публичный репозиторий `sergeulub/diary-app`
(в нём только код). Правило: не переименовывать репозиторий и аккаунт.

Три слоя, каждый общается только с соседним:
| Слой | Ответственность | Пример API |
|---|---|---|
| `src/domain/` | Чистые функции без DOM и БД, покрыты тестами | `logicalDay(now, boundaryHour)`, `streak(filledDays, today)`, `sleepDuration(start, end)`, `buildExport(...)`, `parseImport(json)`, `validateMetricValue(def, value)` |
| `src/db/` | Единственный доступ к IndexedDB (Dexie); позже заменяется при обёртке в Capacitor | `getDay`, `saveDay`, `listDays(from, to)`, `getMetrics`, `saveMetric`, `getMeta`, `setMeta` |
| `src/ui/` | React-экраны и компоненты | `SummaryScreen`, `CalendarScreen`, `SettingsScreen`, `DayForm`, `MoodFace` |

При старте — `navigator.storage.persist()`.
Service worker кэширует всё приложение. Новая версия скачивается в фоне и применяется при следующем запуске.

## 6. Данные (схема Dexie v1)
| Таблица | Ключ | Поля |
|---|---|---|
| `days` | `day` (ГГГГ-ММ-ДД) | `id` (UUID), `metrics` `{ [key]: value }`, `text`, `createdAt`, `updatedAt`, `deletedAt` |
| `metricDefinitions` | `key` | `name`, `type` (`scale` / `time` / `number` / `bool`), `unit`, `order`, `archived`, `primary`, `face` (`mood` / `boredom` / нет), `createdAt`, `updatedAt` |
| `entries` | `id` | Заготовка под дневную ленту: `day`, `text`, `createdAt`, `updatedAt`, `deletedAt`. В MVP пустая |
| `meta` | `key` | `boundaryHour` (6), `lastExportAt`, `schemaVersion` |

- Стартовые метрики: `mood` «Настроение» (`scale`, `primary`, `face: mood`), `boredom` «Скука» (`scale`, `face: boredom`),
  `sleepStart` «Лёг» и `sleepEnd` «Встал» (`time`).
- `scale` — целое 1–5; `time` — строка «ЧЧ:ММ» местного времени; метки `createdAt`/`updatedAt`/`lastExportAt` — ISO 8601
  со смещением часового пояса.
- Новая метрика = новая строка в `metricDefinitions`, без миграции. Архивная скрыта на экране, история остаётся.
  У новых `scale`-метрик — цифры 1–5 вместо мордочек.
- Схема меняется только через `db.version(n).upgrade(...)`, прежние версии не удаляются.

## 7. Экспорт и импорт (контракт, `formatVersion: 1`)
**Экспорт** — одна кнопка → один файл `diary-ГГГГ-ММ-ДД.zip` через системное окно «Поделиться»
(путь: Telegram «Избранное» → Telegram Desktop → папка на ПК). Если `navigator.share` с файлом недоступен —
обычное скачивание. Внутри zip:
1. `backup.json` — весь дневник: `formatVersion`, `exportedAt`, `metricDefinitions`, `days`, `entries`, `meta`.
2. `entries_ГГГГ-ММ-ДД_ГГГГ-ММ-ДД.md` — один файл с днями, у которых `updatedAt` > `lastExportAt`
   (первый экспорт — все дни), по возрастанию даты. Имена файлов латиницей: Проводник Windows может исказить
   кириллицу в zip.

Формат дня в Markdown:
```
## 2026-10-06, вторник
Настроение: 4/5 (хорошо) · Скука: 2/5 · Сон: 23:40–07:10 (7 ч 30 мин)

<текст дня>
```
Пустые метрики пропускаются; архивные метрики со значением выводятся.

`lastExportAt` обновляется только после успешного «Поделиться» или скачивания. Отмена его не меняет.

**Импорт** `backup.json` (или zip с ним): слияние по `day` / `key` / `id`, при конфликте побеждает более свежий
`updatedAt`. Перед импортом — экран-сводка «будет добавлено N, обновлено M». Файлы с неизвестной `formatVersion`
выше текущей отклоняются с понятным сообщением. Импорт старых версий не ломается.

## 8. Визуальный стиль
Тёплый «бумажный» с элементами игривости, палитра «олива».

| Токен | Светлая | Тёмная |
|---|---|---|
| Фон `bg` | `#F2EFE3` | `#181A15` |
| Карточка `surface` | `#FBFAF2` | `#22251E` |
| Текст `ink` | `#252920` | `#E8EADE` |
| Вторичный `muted` | `#666A57` | `#A0A491` |
| Линии `line` | `#DEDCCB` | `#33372D` |
| Акцент `accent` | `#65763F` | `#A9BC7E` |
| Текст на акценте | `#FFFFFF` | `#181A15` |

- **Шкала настроения 1–5** (заливка мордочек и цвет дней в календаре): `#A9B2BE`, `#CFC9B4`, `#E6D69A`, `#BFD08F`, `#94AC62`.
- **Мордочки скуки:** нейтральная заливка `#E3DDC8`. Линии всех мордочек — `#2A2D23`, румянец `rgba(214,120,96,.45)`.
- **Мордочки «от руки»** (SVG из макета, чуть неровный контур):
  - настроение: 1 — грустные бровки, 2 — лёгкая грусть, 3 — ровный рот, 4 — улыбка с румянцем, 5 — открытая улыбка
    и глаза-дуги;
  - скука: 1 — широко открытые глаза, 2 — точки, 3 — полуприкрытые, 4 — глаза-черточки, 5 — закрытые глаза и зевок,
    **без «Z»**.
- **Выбор мордочки:** выбранная — кольцо акцентного цвета и масштаб 1.06, остальные — прозрачность 0.55.
- **Шрифты:** заголовки — Lora 600 (засечки, с кириллицей, вшит в приложение, без Google Fonts — офлайн), остальное —
  системный `-apple-system`.
- **Формы:** скругления карточек 20 px, кнопок 14 px, мягкая тень в светлой теме, без тени в тёмной.
- **Касания:** зоны нажатия ≥ 44 px, `safe-area-inset`. Тема переключается автоматически по системной.

## 9. Напоминание
Без кода приложения: инструкция в Настройках. Основной способ — будильник iOS («Часы» → «Будильник», 23:00, повтор
каждый день, метка «Запиши день», мелодия): звучит, пока его не выключат. Дополнительно — ежедневное напоминание в
«Напоминаниях» или автоматизация «Команд» с «Показать уведомление». Время 23:00 по умолчанию, пользователь меняет сам.

Фаза 0 показала: «Команды» не могут открыть веб-приложение (ни «Открыть приложение», ни «Открыть URL» — второе
открывает Safari), поэтому автооткрытия дневника и виджета «Команд» нет. Дневник открывается с иконки.

## 10. Проверка
**Автотесты (Vitest)** для `domain/`:
- логический день — границы 05:59 и 06:00, полночь, смена часового пояса;
- серия — пустой сегодня, разрыв, первый день;
- сон через полночь;
- проверка значений метрик;
- экспорт → импорт даёт те же данные;
- выбор дней «с прошлой выгрузки»;
- слияние по `updatedAt`;
- отказ при будущей `formatVersion`.

**Чек-лист на iPhone** после каждой фазы:
- установка на экран «Домой»;
- работа в авиарежиме;
- запись → закрыть → открыть;
- экспорт → Telegram → ПК → zip распаковывается, кириллица в `.md` читается;
- импорт бэкапа в чистое приложение.

**Проверено в Фазе 0** (результаты — `docs/phase0-results.md`: 1 — данные сохраняются, 2 — нет, 3 — да,
4 — изолировано):
1. Стирает ли «Очистить историю и данные» в Safari базу веб-приложения с экрана «Домой».
2. Может ли «Команды» открыть само веб-приложение, а не Safari.
3. Отдаёт ли iOS zip через `navigator.share` в Telegram.
4. Насколько изолировано хранилище двух веб-приложений с одного `sergeulub.github.io`.

## 11. Фазы
- **Фаза 0** — скелет PWA на GitHub Pages: установка, офлайн, проверки из §10.
- **Фаза 1** — этот MVP целиком.
- **Фаза 2** — анализ экспорта Claude Code на ПК, дашборды.
- **Фаза 3** — финансы, здоровье, ИИ, нативная обёртка (Capacitor) и настоящий виджет при необходимости.
