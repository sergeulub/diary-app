# Разборы насмотренности — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** разборы рекламы и упаковок внутри записи дня, с фото, экспортом и измеримой целью «Разборы».

**Architecture:** разборы — строки `entries` с `kind: 'review'`; фото — новая таблица `photos` (Dexie v3). Логика — чистые
функции в `src/domain/reviews.ts`, доступ — `src/db/diary.ts`, UI — `src/ui/Reviews.tsx` внутри `DayForm`.

**Tech Stack:** React 19 + TS, Dexie 4, fflate, Vitest + fake-indexeddb.

**Spec:** `docs/superpowers/specs/2026-10-17-reviews-design.md`

## Global Constraints
- Тексты интерфейса — дословно из спецификации («Разбор насмотренности», «Ещё разбор», «ещё не записано», …).
- Схема Dexie v1/v2 не правится; добавляется `db.version(3)`, `schemaVersion: 3`.
- `FORMAT_VERSION = 3`; импорт форматов 1 и 2 продолжает работать.
- Логика без DOM — только в `src/domain/`, с тестами; доступ к IndexedDB — только из `src/db/`.
- Фото: JPEG, длинная сторона ≤ 1600 px, качество 0,8; байты — `Uint8Array`.

## Review Focus
- Двойной тап по «Разбор насмотренности» → ровно один новый разбор (защита `busy`, как в GoalSheet).
- Быстрая диктовка в три поля подряд → ни одно поле не затирает другое (`saveReview` читает и пишет в одной транзакции).
- Удалённый разбор с фото → фото не попадают ни в счёт, ни в Markdown, ни в zip (тест в Task 3).
- Импорт голого `backup.json` формата 3 → фото без файла пропускаются, без ошибки (тест в Task 4).
- Пустой разбор (создан и брошен) → не считается в цели и не выводится в Markdown (тесты в Task 1 и 3).
