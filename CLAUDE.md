# Diary — личный вечерний дневник для iPhone: PWA, работает офлайн, данные только в телефоне

**Стек:** React + TypeScript + Vite, Dexie.js (IndexedDB), vite-plugin-pwa, Tailwind CSS, тесты — Vitest ·
**Адрес навсегда:** `https://sergeulub.github.io/diary-app/` (GitHub Pages, публичный репозиторий `sergeulub/diary-app`) ·
**Запуск / проверка:** `npm run dev` → http://localhost:5173/diary-app/ · `npm test` · `npm run build` ·
деплой — push в `main` (GitHub Actions → Pages)

**Утверждённая спецификация MVP — `docs/superpowers/specs/2026-10-06-diary-mvp-design.md`.** Она главнее этого файла
в деталях экранов, правил, экспорта и стиля. `ОПИСАНИЕ.md` — обоснования: варианты установки на iOS, аналоги, риски,
источники. Макеты — Claude Design «Дневник — палитры» (https://claude.ai/artifact/4qTAKHzpewv4E3fPZtASiq).

## Что это
Вечерний дневник одного человека (автора): перед сном за 1–3 минуты отметить настроение, скуку, сон и надиктовать,
как прошёл день. Календарь для правки любого прошедшего дня, экспорт для анализа. Записей в течение дня нет.
В App Store не публикуется: открыть в Safari → «На экран Домой», дальше работает без интернета.
Сначала минимальная база; анализ, дашборды, финансы, здоровье, ИИ наслаиваются потом.

## Договорённости с пользователем
- Интерфейс и тексты — на русском. Стиль — тёплый «бумажный» с элементами игривости, палитра «олива».
- У пользователя Windows, Mac нет; телефон — iPhone 11, iOS 26.7.1 (экран 414×896 pt).
- Без серверов, аккаунтов, аналитики и отправки данных. Интернет нужен только для установки и обновления кода.
- **Репозиторий публичный:** в коде, тестах, документах и коммитах — только вымышленные примеры; никаких сведений о
  пользователе, его учёбе, знакомых и записях. Личное — только в телефоне и в `LIFE/`.
- **OneDrive не использовать** нигде: пользователь его отключил. Перенос экспорта на ПК — через Telegram «Избранное».
- Защита дневника (PIN, Face ID, шифрование) не нужна.
- Анализ записей делает Claude Code на ПК по экспортированным файлам, не приложение. Анализ выгрузок, отчёты и
  дашборды — проект `LIFE/diary-analysis` (там формат данных для анализа и правила подсчётов).
- Перед дизайнерской работой — сначала спросить о стиле и показать план, потом делать.
- **Визуал каждой доработки сначала согласуется в Claude Design**, в одном и том же артефакте
  https://claude.ai/artifact/54x6G4dAzDa72P6feRpBM1. Туда добавляются новые артборды, новый артефакт не создаётся.
  Код экранов пишется только после того, как пользователь одобрит макеты.

## Архитектурные правила (не нарушать)
1. **Адрес приложения фиксирован навсегда.** IndexedDB привязан к origin: другой адрес — пустое приложение.
   Не переименовывать репозиторий и аккаунт. Переезд — только через экспорт/импорт.
2. **Схема версионируется** через `db.version(n).upgrade(...)` в Dexie; прежние версии не удалять.
3. **У каждой записи** `id` (UUID), `createdAt`, `updatedAt`, `deletedAt` (мягкое удаление) — задел под синхронизацию.
4. **Логический день** — граница 06:00 (настраивается): запись в 02:30 относится к прошлому дню.
   Метки времени — ISO 8601 со смещением часового пояса.
5. **Экспорт — контракт:** один `diary-ГГГГ-ММ-ДД.zip` = `backup.json` (весь дневник, для импорта) +
   `entries_ГГГГ-ММ-ДД_ГГГГ-ММ-ДД.md` (один файл с днями, изменёнными с прошлого экспорта, для Claude).
   Имена файлов латиницей. Формат менять только с повышением `formatVersion`; импорт старых версий не ломать.
   Сейчас `formatVersion: 4` (4 — операции накоплений «Отложил»/«Взял»; 3 — разборы насмотренности; фото — файлами `photos/<id>.jpg` в том же zip, в `backup.json`
   только их метаданные).
6. **Все оценки — метрики:** новый пункт — строкой в `metricDefinitions`, без миграции схемы.
7. **Логика** (даты, серия, сон, экспорт/импорт, метрики) — чистые функции в `domain/` без DOM, с тестами.
8. **Доступ к данным** — только через слой `db/`: чтобы позже обернуть в Capacitor без переписывания.
9. При старте — `navigator.storage.persist()`; баннер о бэкапе, если с последнего экспорта прошло > 7 дней.

## Модель данных v3
| Таблица | Поля |
|---|---|
| `days` | `day` (ключ, ГГГГ-ММ-ДД), `id`, `metrics{key: value}`, `text`, `createdAt`, `updatedAt`, `deletedAt` |
| `metricDefinitions` | `key`, `name`, `type` (scale / time / number / bool), `unit`, `order`, `archived`, `primary`, `face` |
| `entries` | Записи внутри дня; сейчас — разборы насмотренности: `id`, `day`, `kind: 'review'`, `text` (что это, для кого, что обещает), `verdict`, `change`, метки, `deletedAt` |
| `photos` | `id`, `entryId`, `day`, `type`, `bytes` (Uint8Array, JPEG ≤ 1600 px), метки, `deletedAt` (у удалённого пустые `bytes`) |
| `meta` | `boundaryHour`, `lastExportAt`, `schemaVersion` |
| `financeCategories` | `key`, `kind` (expense / income), `name`, `importance` (need / useful / optional, только траты), `order`, `archived` |
| `transactions` | `id`, `day`, `kind` (expense / income / save «Отложил» / withdraw «Взял»), `amount` (копейки), `categoryKey` (у save/withdraw пустой), `note`, `createdAt`, `updatedAt`, `deletedAt` |
| `goals` | `id`, `month` (ГГГГ-ММ), `text`, `area`, `target` (измерение, необязательно), `order`, метки, `deletedAt` |

Стартовые метрики: `mood` «Настроение» (главная, красит календарь), `boredom` «Скука», `sleepStart` «Лёг»,
`sleepEnd` «Встал».

## Экраны
Нижняя панель: **Итог** (текущий логический день, автосохранение, серия дней, строка трат за сегодня, разборы
насмотренности под текстом дня) ·
**Финансы** (месяц: доход, траты, отложено — только вручную «Отложил» минус «Взял», всего в накоплениях; траты по важности и категориям; операции по дням; быстрый ввод «+») ·
**Цели** (цели месяца, прогресс измеримых, в том числе «Разборы») · **Календарь** (месяц, дни по цвету настроения, тап → правка дня) ·
**Настройки** (метрики, категории, граница дня, экспорт/импорт).
Настроение и скука — нарисованные мордочки «от руки» (SVG), не эмодзи. Токены цвета и правила — в спецификации MVP,
§8; цвета важности и макеты финансов и целей — в спецификации финансов, §6.1; разборы — спецификация
`docs/superpowers/specs/2026-10-17-reviews-design.md`.

## Структура
- `src/domain/` — чистая логика (даты, метрики, сон, серия, календарь, деньги, финансы, цели, разборы, экспорт, импорт) с
  тестами рядом (`*.test.ts`).
- `src/db/` — Dexie-схема `diary` v3 и функции доступа (`diary.ts`), `navigator.storage`; тесты на `fake-indexeddb`.
- `src/ui/` — экраны Итог, Календарь, Настройки; общая форма дня `DayForm` с разборами `Reviews.tsx`; мордочки `faces.tsx`.
- `public/` — иконки PWA (генерируются `npm run icons` из `public/icon.svg`).
- `docs/superpowers/` — спецификации и планы; `docs/phase0-results.md`, `docs/phase1-results.md` — проверки на iPhone.

## Этапы
- **Фаза 0** — скелет PWA на GitHub Pages → установить на iPhone → авиарежим и проверки из спецификации §10.
- **Фаза 1** — MVP по спецификации.
- **Фаза 2** — финансы (доходы, траты, категории с важностью) и цели на месяц в приложении.
